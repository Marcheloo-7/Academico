DETALLE DE CORE ASSETS
Sistema de Gestión Académica
Documento | Detalle funcional de Core Assets (CA-001 – CA-006)
Proyecto | Sistema de Gestión Académica (LPS – Dominio Académico)
Stack tecnológico | Python (FastAPI) — React
Stack de comunicación | GraphQL
Usuarios base del sistema | Docente (rol Docente) y Administrador (rol Administrador)
Módulos funcionales | Estudiante (CRUD), Docente (CRUD), Cursos, Inscripciones
Versión | 1.0
Este documento describe, para cada uno de los seis primeros Core Assets del catálogo del Dominio Académico, qué funcionalidades y elementos debe contener su implementación, tomando como base el stack tecnológico definido (FastAPI + React + GraphQL) y el alcance funcional del producto derivado: dos usuarios base (Docente y Administrador) y cuatro módulos de negocio (Estudiante, Docente, Cursos e Inscripciones).
Especificación Técnica Base
Esta sección complementa el detalle funcional de cada Core Asset (CA-001 a CA-006) con una base técnica breve: estructura de archivos, firmas clave, modelo de datos tipado y esquema GraphQL en SDL. El objetivo es fijar un esqueleto común antes de generar el código, sin decidir todavía la implementación completa de cada asset.

CA-001 — Autenticación y Autorización
Módulo encargado del inicio de sesión y del control de acceso de los dos usuarios base del sistema: Docente (rol Docente) y Administrador (rol Administrador). Utiliza JSON Web Tokens (JWT) para mantener sesiones seguras y sin estado, y protege tanto las rutas del frontend como los resolvers GraphQL del backend.
Qué debe tener
Formulario de inicio de sesión en React (correo/usuario y contraseña).
Mutation GraphQL "login" que valida credenciales y retorna el token JWT junto con el rol del usuario.
Generación de JWT con claim de rol ("docente" o "administrador") y tiempo de expiración configurable.
Middleware/decorador en FastAPI que valida el token en cada resolver protegido.
Cierre de sesión (logout) e invalidación del token en el cliente.
Enrutamiento protegido en React: el Administrador accede a todos los módulos; el Docente solo a sus cursos y a la lista de estudiantes inscritos en ellos.
Manejo de errores de autenticación (credenciales inválidas, token expirado, acceso no autorizado).
Tecnologías relacionadas
React (formulario y contexto de sesión) · FastAPI (endpoint/resolver de login) · GraphQL (mutation de autenticación) · JWT (emisión y validación de tokens).
Dependencias
Core Asset requerido | Motivo
CA-003 | Requiere el rol del usuario (Docente/Administrador) para incluirlo como claim en el token y aplicar restricciones de acceso.
CA-002 — Gestión de Usuarios
Módulo que administra las cuentas de acceso del sistema (Docente y Administrador) y, además, implementa los módulos de negocio Estudiante y Docente como operaciones CRUD independientes, ya que ambos son entidades académicas gestionadas desde el panel de Administrador.
Qué debe tener
Gestión de cuentas — CRUD de cuentas de usuario (Docente, Administrador): creación, edición, consulta, desactivación.
Módulo Estudiante — Módulo Estudiante (CRUD): registrar, listar, editar y eliminar estudiantes (nombre, código, correo, datos de contacto).
Módulo Docente — Módulo Docente (CRUD): registrar, listar, editar y eliminar docentes (nombre, correo, especialidad), vinculado opcionalmente a una cuenta de usuario con rol Docente.
Listados paginados y búsqueda/filtrado por nombre, código o correo en ambos módulos.
Validación de datos obligatorios y formatos (correo, campos requeridos) antes de persistir.
Vistas React para el panel de Administrador (gestión completa) y vista de solo lectura para el Docente sobre sus propios datos.
Tecnologías relacionadas
React (vistas de administración) · FastAPI (resolvers GraphQL de usuarios/estudiantes/docentes) · PostgreSQL (persistencia).
Dependencias
Core Asset requerido | Motivo
CA-001 | Solo usuarios autenticados pueden acceder a las operaciones de gestión.
CA-003 | Determina qué operaciones puede ejecutar cada rol (el Docente no gestiona cuentas de usuario).
CA-005 | Persistencia de los datos de Usuario, Estudiante y Docente.
CA-003 — Gestión de Roles y Permisos
Módulo que administra el control de acceso basado en roles (RBAC) del sistema, limitado a los dos roles definidos para este producto: Docente y Administrador.
Qué debe tener
Definición fija de dos roles base: Docente y Administrador (no se requiere creación dinámica de roles adicionales para este producto).
Matriz de permisos por rol:
Administrador — acceso completo a los módulos Estudiante, Docente, Cursos e Inscripciones, y a la gestión de cuentas de usuario.
Docente — acceso a sus cursos asignados, a la lista de estudiantes inscritos en ellos y a la funcionalidad de inscripción de estudiantes; sin acceso a la gestión de cuentas ni a cursos de otros docentes.
Verificación de permisos en cada resolver/mutation de GraphQL antes de ejecutar la operación.
Inclusión del rol como claim dentro del JWT emitido por CA-001.
Decoradores/dependencias de FastAPI reutilizables para restringir endpoints por rol.
Tecnologías relacionadas
FastAPI (verificación de permisos en resolvers) · JWT (claim de rol).
Dependencias
Core Asset requerido | Motivo
CA-001 | Los roles se incorporan al token JWT generado tras la autenticación.
CA-005 | Persistencia de la relación usuario–rol.
CA-004 — Sistema de Diseño
Librería de componentes visuales y lineamientos de estilo que da soporte a las interfaces de los módulos Estudiante, Docente, Cursos e Inscripciones, así como a los paneles diferenciados de Administrador y Docente.
Qué debe tener
Componentes React reutilizables: tablas de listado (estudiantes, docentes, cursos, inscripciones), formularios, modales de confirmación, botones y campos de búsqueda/filtro.
Paleta de colores institucional y tipografía definidas como tokens/variables CSS.
Layout base de dashboard con navegación diferenciada según rol (menú completo para Administrador, menú reducido para Docente).
Componentes de estado (badges) para mostrar, por ejemplo, el estado de una inscripción (activa, cerrada, cupo lleno).
Guía de estilos con ejemplos de uso de cada componente.
Tecnologías relacionadas
React · CSS/SCSS (tokens de diseño).
Dependencias
Sin dependencias directas de otros Core Assets.
CA-005 — Configuración de Base de Datos
Configuración centralizada de la conexión a PostgreSQL y de los modelos ORM (SQLAlchemy) que representan las entidades del dominio académico: Usuario, Docente, Estudiante, Curso e Inscripción.
Qué debe tener
Configuración de conexión a PostgreSQL mediante variables de entorno (host, puerto, credenciales, nombre de la base).
Modelo Usuario (correo, contraseña encriptada, rol) para las cuentas de Docente y Administrador.
Modelo Docente (nombre, correo, especialidad) y modelo Estudiante (nombre, código, correo, datos de contacto).
Modelo Curso (nombre del curso, docente a cargo, periodo académico) con relación al Docente responsable.
Modelo Inscripción (estudiante, curso, fecha de inscripción, estado) que representa la relación muchos-a-muchos entre Estudiante y Curso, e incluye los campos necesarios para aplicar validaciones académicas (por ejemplo, cupo disponible o inscripción duplicada).
Pool de conexiones configurable y utilidades de sesión reutilizables entre resolvers.
Plantilla de variables de entorno (.env.example) y modelos base con timestamps de creación/actualización.
Tecnologías relacionadas
PostgreSQL · SQLAlchemy (ORM) · FastAPI (integración con la capa de resolvers).
Dependencias
Sin dependencias directas de otros Core Assets.
CA-006 — Esquema GraphQL Base
Capa de comunicación GraphQL entre el frontend React y el backend FastAPI, que expone las queries y mutations necesarias para operar los módulos Estudiante, Docente, Cursos e Inscripciones.
Qué debe tener
Tipos GraphQL base: User, Docente, Estudiante, Curso e Inscripcion, reflejando los modelos de CA-005.
Queries: listar/consultar estudiantes, docentes, cursos (con su docente y lista de estudiantes) e inscripciones, con soporte de filtros y paginación.
Mutations de gestión: crear, actualizar y eliminar estudiantes, docentes y cursos.
Mutation de inscripción — Mutation "inscribirEstudiante": inscribe a un estudiante en un curso aplicando validaciones académicas (curso con cupo disponible, estudiante no inscrito previamente en el mismo curso, periodo académico vigente).
Mutation "login" expuesta por CA-001 e integrada en el mismo esquema.
Resolvers protegidos según el rol del usuario autenticado (Administrador vs. Docente), usando la verificación de CA-003.
Formato de respuesta de error consistente para las validaciones académicas y de negocio.
Cliente Apollo configurado en el frontend React para el consumo de queries y mutations.
Tecnologías relacionadas
GraphQL (Strawberry/Ariadne sobre FastAPI) · React Apollo Client.
Dependencias
Core Asset requerido | Motivo
CA-001 | Protección de queries y mutations mediante autenticación (JWT).
CA-003 | Restricción de operaciones según el rol del usuario.
CA-005 | Los resolvers acceden a la base de datos para resolver las consultas y mutations.
Nota: los módulos de negocio Cursos e Inscripciones se apoyan directamente en CA-005 (persistencia) y CA-006 (API GraphQL); no constituyen Core Assets independientes dentro de este alcance de seis assets, sino funcionalidad específica del producto derivado construida sobre ellos.
